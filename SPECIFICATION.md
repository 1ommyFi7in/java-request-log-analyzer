# Техническое задание · Анализатор журнала запросов

[← К README](README.md)

## Рабочий сценарий
Дежурный хочет узнать, какие маршруты дали ошибки во время инцидента с 09:00 до 10:00. Сырой файл большой, часть записей повреждена, два режима обработки должны давать одинаковый отчёт для последующей автоматической сверки.

## Порядок реализации и контракт

1. Напиши разбор строки и чтение файла. Время UTC, путь начинается с `/`, статус 100–599, длительность в мс от 0. Пустая или повреждённая строка считается пропущенной даже вне выбранного интервала.
2. Построй агрегаты и итоговую сортировку. `TOP` сортируется по частоте по убыванию и пути по возрастанию, `AVG` по пути по возрастанию. Дроби округляются HALF_UP до двух знаков. При пустом входе остаются счётчики без `TOP` и `AVG`.
3. Вынеси выбор между циклом и Stream в Strategy и сравни stdout и stderr побайтово. Парсер общий. Для измерения времени подготовь отдельный генератор фикстуры.

| Воспроизведение | Ожидаемое поведение |
| --- | --- |
| Из примера взять окно `[09:01:00Z,09:02:00Z)` | 1 запрос, 1 ошибка, 1 пропуск, только `/orders` с 70.00 ms |
| Без фильтра, добавить одну корректную строку `/products` с 40 ms | Маршруты с частотой 2 идут как `/orders`, `/products`; среднее для `/products` 30.00 |
| Неверный фильтр времени или отсутствующий файл | Ненулевой код выхода, понятная причина в stderr, частичный отчёт отсутствует |
| 100 000 строк на 20 путей | Укажи размер файла, JDK, память, время и контроль равенства двух отчётов |

К сдаче приложи две фикстуры, список вызовов CLI и короткое объяснение расхода памяти на агрегаты.

## Функциональные требования

- [ ] `analyze <file> [--from <instant>] [--to <instant>] [--status <100–599>] [--mode loop|stream]` читает UTF‑8 и применяет фильтры.
- [ ] Вывести число запросов, число ошибок (400–599), топ-10 URL по частоте и среднюю длительность по каждому URL. При равной частоте сортировать по URL, среднее округлять до двух знаков.
- [ ] Пропускать повреждённые строки, выводить номер и причину в stderr и считать пропуски. Неверный фильтр или недоступный файл дают ошибку запуска.
- [ ] Режимы `loop` и `stream` дают одинаковый результат. Выбрать режим через Strategy и подобрать коллекции под агрегацию.

## Формат данных

Строка — `timestamp;url;status;durationMs`. Время ISO 8601 UTC, длительность — неотрицательное целое. Интервал фильтра `[from, to)`, URL — путь без разделителя.

## Пример ввода и вывода

```text
2026-01-15T09:00:00Z;/orders;200;30
2026-01-15T09:01:00Z;/orders;503;70
2026-01-15T09:02:00Z;/products;200;20
bad line
```

```text
> analyze requests.log --mode stream
REQUESTS 3
ERRORS 1
SKIPPED 1
TOP /orders 2
TOP /products 1
AVG /orders 50.00 ms
AVG /products 20.00 ms
```

В stderr появится `line 4: invalid format`.

## Нефункциональные требования

- [ ] Читать файл последовательно, хранить агрегаты по URL, закрывать файловый stream и описать расход памяти.
- [ ] Прогнать 100 000 строк, записать время, размер файла, число разных URL и условия измерения.

## Приёмка

- [ ] Сравнить режимы на примере, пустом файле, границе периода и равных частотах. Ручной расчёт по контрольному файлу из 20 строк совпадает с отчётом.
